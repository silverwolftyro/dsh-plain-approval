# 说人话 · dsh-plain-approval

> **让每一条提权命令，都先说人话。**

DSH 弹出一个 `danger-full-access` 审批窗口时，非技术用户看到的是一串 `pwsh -Command ...`。
本插件在审批卡片上，用**固定大白话**把这条命令讲清楚：

| # | 段落 | 例子（命令 `ls -la`） |
|---|---|---|
| 0 | **背景**（v0.4 新增） | 结合你最近的指令（帮我测试审批弹窗），这一步是本回合的第 1 次操作。 |
| 1 | **干什么** | 列出当前文件夹的所有文件和文件夹的详细信息 |
| 2 | **碰什么** | 当前目录下的文件和文件夹 |
| 3 | **读还是写** | 只读 |
| 4 | **风险等级** | 安全（绿）／注意（黄）／危险（红） |
| 5 | **建议** | 可以允许 |
| 6 | **后果** | 最多泄露本机文件的名字和大小，不会改动任何文件。 |
| 7 | **收益** | 让你看到文件夹里有哪些文件、多大、什么时候改的。 |

翻译放在**原始命令上方**，原始命令完整保留在下方。风险用**颜色 + 文字**双重标注
（安全=绿、注意=黄、危险=红），色盲用户一样能看懂。支持一键复制。

只要看一眼第 6、7 段，用户就能决定点不点「允许」。

> ### ⚠️ 这个插件只翻译，**不替你做决定**
>
> 它给你的是**信息**，不是**许可**。风险等级来自本地规则与语言模型的判断，**会出错**。
> 无论它标绿标红，**点不点「允许」永远是你自己的决定**。
> 遇到标红的命令，请自己再看一眼原始命令再决定 —— 别因为「插件说是绿的」就直接点。
>
> 它也**不会**自动批准任何审批。要完整了解它会做什么、不会做什么，见 [SECURITY.md](./SECURITY.md)。

**v0.4 起默认「装完就能用」**：第一次启用会弹一次向导（默认选「自动」），
用 DSH 自己的 AI 翻译，**不要求安装任何额外软件、不要求填任何 Key**。
本地 Ollama 只在用户主动选择时才启用（并且带防 OOM 护栏与设备能力检测）。

## 当前版本

**v0.6.1** —— **默认分析深度改为「一律 L2」**。

| 层 | 输入 | 耗时 | 成本 | 意图质量 |
|---|---|---|---|---|
| **L1 基础** | 只有命令文本，**零模型调用** | <100ms | 0 | 规则拼的字面描述 |
| **L2 标准** | 命令 + 会话上下文 + 模型 | 2~10 秒 | ~0.001~0.002 元 | 结合上下文的真实意图 |

设置页 →「分析深度」三个选项：

| 选项 | 什么时候选它 | 取舍 |
|---|---|---|
| **一律 L2（默认）** | 想要最准的意图 | 每条命令都花一次模型的钱，多等几秒 |
| **自动** | 大部分命令无所谓，想省钱 | 安全命令走 L1（秒出、0 成本），但那些命令的意图是字面描述 |
| **尽量 L1** | 只在少数复杂场景要模型 | 最省，但最不准 |

**为什么默认是 L2 而不是自动**：安全命令占了大多数。
默认走 L1 意味着大多数时候你看到的是「用 Python 运行脚本」，
而不是「你刚才让它补全 ComfyUI 缺的画图模型」。
识别正确度是这插件存在的理由，所以默认给最准的那档 —— 想省钱可以自己切。

> ⚠️ **危险命令永远走 L2，任何设置都降不下来。**
> L1 看不懂复杂脚本，而危险恰恰最需要被认真解释 ——
> 宁可多花一次模型调用的钱，也不给危险操作一个「看起来没事」的快速通道。

卡片底部固定显示 `本次分析 · 耗时 · 费用`；L1 时附「升级到 L2」按钮。

**关于风险等级**：模型只能把风险改得**更保守**，不能改得更宽松 ——
本地规则始终是下限。这与需求里「风险由 L2 决定」有意不同，理由见 CHANGELOG。

v0.6.0 引入分层；v0.5.10 修删除目标误判；v0.5.9 修联网下载误报；v0.5.8 卡片即时意图。

⚠️ **v0.5.6 尚未在真机上验证**（真机验证过的只有 v0.4.6-safe 的接管路径）。
装之前请先读 [SECURITY.md](./SECURITY.md)。

> **升级建议清一次缓存**（设置页「翻译缓存」有清空按钮，或删 `cache.sqlite`）。

升级步骤见 [升级指南](./升级指南-v0.5.0-stable.md)。

## ⛔ 严重警告：请勿使用 v0.4.2 / v0.4.3

> **v0.4.2 与 v0.4.3 会导致 DSH 界面完全卡死，并把渲染进程内存吃到 900MB+ 直到被系统强杀
> （`Desktop renderer exited: killed`），重启也会复发。**
>
> **请使用 v0.4.6-safe；若要回退，用 v0.4.1 / v0.3.0。**
>
> 根因是这两个版本里有一段 DOM 注入用了 `MutationObserver` 观察整个 `document.body`，
> 而回调里又无条件修改 DOM，形成微任务自激循环（卡死 + 内存无限增长）。
> **补充更正：真正的引爆点不是浮窗拖动**（拖动的监听器当时有正确清理），
> 而是上面这个 MutationObserver 自激循环。拖动功能同样已永久移除 ——
> 它不是元凶，但在这个架构里没有存在价值。
> v0.4.5 已把这段代码彻底删除，v0.4.6-safe 进一步把同类放大路径封死并补齐回归测试。
> 详见 [CHANGELOG](./CHANGELOG.md) 与 [修复说明](./修复说明-v0.4.6-safe.md)。

## 安装

### 方式一：从 GitHub Release 的 .tgz 安装（推荐，不依赖 npm 发布）

1. 下载 Release 里的 `dsh-plain-approval-0.4.5.tgz`。
2. 在 DSH 里用插件管理器安装该 tgz（`plugin_manager` 的 `install_bundle`，
   `target` 传 tgz 的绝对路径）。插件管理器会同时完成依赖安装与组合包登记。
3. 或者用 DSH 自带的 CLI：

   ```powershell
   dsh plugin --profile desktop add "C:\path\to\dsh-plain-approval-0.4.5.tgz"
   ```

   > `dsh plugin add` 只把包装进 profile 的 `node_modules`。还要确认 profile 的
   > `package.json` → `dsh.profile.bundles` 里包含 `dsh-plain-approval`
   > （插件管理器的 `install_bundle` 会自动写这一行）。

4. 重启 DSH（替换已安装的包需要重启才会加载新的 JS 模块）。

### 方式二：直接从源码目录安装（开发时）

把本目录路径交给插件管理器的 `install_bundle` 即可，无需 npm 发布。

### 装好之后

- 设置页出现新板块：**设置 → 说人话**，里面有两条通道的状态灯、一键测试、
  导出诊断日志、清空缓存与全部配置。
- 下一次提权审批时，卡片就会变成白话卡片。

## 两种翻译引擎的准备步骤

**v0.4 起默认是「API 优先」**：第一次启用会弹一次向导，默认选中
「**自动（推荐）**」——用 DSH 自己的 AI 翻译，**什么都不用装**。

| 引擎策略 | 链路 | 适合谁 |
|---|---|---|
| `auto`（默认） | DSH 的 AI（`ctx.llm`）→ 凭据直连 HTTP | 所有人，尤其是完全不懂技术的用户 |
| `local-first` | Ollama → DSH 的 AI → 直连 | 有显卡、愿意折腾、想省额度的人 |
| `ollama` | 只用本地 Ollama | 离线环境 |
| `deepseek` | 只用你自己填的 Key 直连 | 想用自己的账号计费 |

**`auto` 的链路里没有 Ollama** —— 禁止在用户没主动选本地时静默调用它。

### 通道 A：本地 Ollama（需要自己安装，默认折叠）

> 只有你在向导里选了「本地免费」，或本机确实已经装好 Ollama，这个面板才会自动展开。

1. 安装 Ollama：<https://ollama.com/download>（Windows 装完会自动常驻托盘）。
2. 拉取模型（默认 `qwen2.5:7b`，约 4.7 GB）：

   ```powershell
   ollama pull qwen2.5:7b
   ```

3. 确认它在跑：

   ```powershell
   curl http://127.0.0.1:11434/api/tags
   ```

4. 打开 DSH「设置 → 说人话」，通道 A 的状态灯应该是**绿色**。
   - 黄色 = Ollama 起来了但没拉模型，按提示执行 `ollama pull <模型名>`；
   - 红色 = 连不上 Ollama（没装 / 没启动 / 地址填错），或**本机配置不足已被强制降级**。

> 小贴士：Ollama 首次调用需要把模型读进显存/内存，本机实测冷启动 20-35 秒。
> 超过设置里的「超时」就会直接降级到通道 B（这是设计如此：宁可降级，也不让用户干等）。
> 想避免，可以打开「允许 Ollama 常驻显存」，或把超时调到 60000ms。
>
> **防 OOM**：本地通道默认串行（一次只跑一条）、命令截断到 2000 字符、
> `num_ctx` 限制到 2048、用完即卸载；连续 3 次失败会自动熔断 5 分钟。
> 详见 [边界情况与降级行为](#边界情况与降级行为)。

### 通道 B：直接用 DSH 的 DeepSeek API（开箱即用、会消耗额度）

**不需要填任何东西。** 插件按下面的顺序自动找 Key：

1. `ctx.llm`（DSH 的模型路由）——优先用这条，插件连 Key 都不碰，
   用的就是 DSH 当前配置的 provider / model（本机是 `deepseek-official` / `deepseek-flash`）。
2. DSH 凭据服务里的 `DEEPSEEK_API_KEY`（和 DSH 用的是**同一个 Key**，
   在 DSH「设置 → 模型」里维护）。
3. 兜底：插件设置页里的「高级 → DeepSeek API Key」。

只有这两条都走不通时，才需要你手动填一次 Key——那就说明 DSH 本身也没配好。
装好之后，通道 B 的状态灯应是绿色。

## 配置说明

两种改法都行，**设置页改的优先级更高**：

- 图形界面：**设置 → 说人话**；
- 配置文件：`$DSH_HOME/plain-approval/settings.json`（`$DSH_HOME` 默认 `~/.dsh`）。

也可以在 profile 的 patch 里改这一行（优先级最低）：

```yaml
- id: plain-approval
  name: dsh-plain-approval
  config:
    engine: auto
```

|---|---|---|---|

| 4 | `ollama.timeoutMs` | `10000` | 通道 A 超时，超时即降级，不阻塞审批 |
| 5 | `ollama.maxCommandChars` | `2000` | **防 OOM**：送进 Ollama 的命令长度上限（字符） |
| 6 | `ollama.numPredict` | `512` | **防 OOM**：显式限制生成 token，不允许无上限生成 |
| 7 | `ollama.numCtx` | `2048` | **防 OOM**：显式限制上下文窗口 |
| 8 | `ollama.maxConcurrency` | `1` | **防 OOM**：Ollama 最大并发（1-2） |
| 9 | `ollama.maxQueue` | `5` | **防 OOM**：排队上限，超了直接降级 |
| 10 | `ollama.minFreeMemoryGB` | `2` | **防 OOM**：可用内存低于此值就不调用 Ollama |
| 11 | `ollama.breakerFailures` / `breakerMinutes` | `3` / `5` | **防 OOM**：连续失败几次熔断、熔断多少分钟 |

| 13 | `device.enabled` | `true` | 是否启用设备能力检测与强制降级 |

| 20 | `deepseek.model` | **空** | 空 = 跟随 DSH 当前选择的模型 |
| 21 | `deepseek.apiStyle` | `auto` | `auto` / `openai` / `anthropic` |

| 28 | `ui.conflictResolved` | `false` | 冲突三选一是否已选过；`false` 时检测到冲突会问**一次** |

### 首次启用向导（v0.4 任务三）

第一次启用插件时，右下角会**弹一次**（用浮层实现，不抢任何功能层插件的槽位）：

| 选项 | 行为 |
|---|---|
| **A 自动（推荐，默认选中）** | `engine = 'auto'`：用 DSH 内置的 AI 翻译（`ctx.llm`）。什么都不用装、不用填 Key |
| B 本地免费 | `engine = 'local-first'`：用自己电脑上的 Ollama，需要先安装；配置偏低时会提示风险 |
| C 我自己填 API Key | `engine = 'deepseek'`：用你自己填的 Key 直连 |

- DSH 没配 API Key 时，A 会置灰并提示「请先在 DSH 设置 → 模型里配置 API Key，或选本地 Ollama」。
- 选完写入 `ui.onboarded = true`，之后不再打扰；设置页顶部有「重新运行初始设置」。
- **默认永远不推荐 Ollama**：通道 A 面板默认折叠，只有用户显式选了本地、
  或本机确实已装好 Ollama（探测为绿）时才自动展开。
- **禁止静默调用 Ollama**：`auto` 模式的链路是 `ctx.llm → 直连 HTTP`，
  里面没有 Ollama；只有 `local-first` / `ollama` 才会走本地。

### 本地通道的风控档位（v0.4.1）

选「本地免费」时会不会弹警告、要不要勾风险确认，由三档决定：

| 档位 | 条件 | 表现 |
|---|---|---|
| `none` | **Ollama 在跑且模型在**（最优先）/ 硬件达标 | 不弹任何警告，直接可用 |
| `soft` | 读不到硬件信息 / 硬件一般偏低 | 只提示一句「建议用 API」，不拦、不要求勾选 |
| `hard` | 真·检测到不达标（显存 <6GB 或 内存 <8GB） | 才要求勾「我明白风险，仍要启用本地通道」 |

判定细节：

- 显存靠 `nvidia-smi`（PATH + `C:\Windows\System32\nvidia-smi.exe` 双重尝试）
  → `wmic` → PowerShell CIM 逐级降级；
- **内存阈值带 1GB 容差**：Windows 保留内存后 16GB 机器只报 15.4–15.9GB，
  没有容差会永远判「偏低」；
- **读不到 GPU 时判 `unknown`**（不是「不可用」），并在设置页提供
  「手动填显存」输入框，填了就按你给的值算；
- 有独显且显存 ≥8GB 时，系统内存闸门自动放宽到 0.8GB
  （模型跑在显存里，系统内存不该一票否决）。

`caretakerPlugins` 的默认值：
`dsh-reject-message`、`dsh-hover-approve`、`approval-zh`、`@local/approval-zh`、
`dsh-armory`、`dsh-compat-vet`、`dsh-integration-settings`。

> **v0.5.0-stable 起这个名单只用于提示，不参与任何决策。**
> 插件**不再调用** `conversation.composer` 上任何条目的 `select()`，
> 也不再看 `priority`。它只在启动时**只读**地扫一次条目元数据（locale / registrant /
> 组件名），用来在设置页显示「检测到 XXX 也在占用审批卡槽位」，以及在你还没选过时
> 弹一次三选一。是否接管完全由 `ui.slotMode` 决定，写进配置后一直生效。

| 效果 | 下次同一条命令**不弹窗直接放行**，并写审计日志 |
| 撤销 | 设置 → 说人话 → 「长期同意」面板：逐条撤销 / 一键清空 |
| 授权表 | `$DSH_HOME/plain-approval/grants.json`（完整哈希 + 前 160 字预览） |
| 审计日志 | `$DSH_HOME/plain-approval/audit.jsonl`：时间 / 命令哈希 / 翻译结果 / 授权规则 ID / 工作区，**不含命令原文** |

**安全底线**（写死在代码里，不靠 UI 约束）：

1. 「注意」「危险」命令**永远**没有长期同意入口；即使手动构造请求，
   服务端会重新跑一遍本地规则，不是「安全」直接 403。
2. 授权表**不能通过配置文件批量导入**：设置保存接口会剔除
   `grants` / `grantList` / `longTermApprovals` / `alwaysAllow` / `allowList` / `whitelist`。
3. 自动放行前会再校验一遍「授权条目 risk=安全 **且** 本次规则判定=安全」。

### 通道 B 的目标是怎么定出来的（不硬编码）

v0.2 起插件不再写死 `https://api.deepseek.com`，而是按下面的顺序解析
（设置页「通道 B 目标」和「能力自检」里能看到每一层的实际来源）：

1. 插件设置里的 `deepseek.baseUrl`；
2. 环境变量 `DEEPSEEK_BASE_URL`（DSH 官方适配器认这个变量）；
3. profile / `$DSH_HOME` 下 `cordis.yml` / `cordis.patch.yml` 里 `llm-deepseek` 行的 `baseURL`；
4. DSH 官方默认 `https://api.deepseek.com/anthropic`。

协议自动匹配：baseUrl 以 `/anthropic` 结尾走 **Anthropic Messages**
（`POST {base}/v1/messages`，`x-api-key` 头）；
否则走 **OpenAI 兼容**（`POST {base}/chat/completions`，`Authorization: Bearer`）。
两个协议、两条真实链路都已实测通过（见「开发者：本地自测」的 L1 / L2）。

## 界面：卡片与浮窗

### 两种显示模式，内容永远只出现一次

DSH 的审批卡片槽位是「一个位置一个主人」。本插件有三种姿态，**由设置页的
「审批卡片模式」决定，插件不会自动改变**：

| 模式（`ui.slotMode`） | 谁渲染卡片 | 七段在哪里 |
|---|---|---|
| **`takeover`（默认）** | 说人话自己 | **只在卡片里**，浮窗不出现 |
| **`overlay`** | 别的插件（如 `dsh-reject-message`）或 DSH 原生 | **只在右下角浮窗里** |
| **`off`** | 同上 | 不显示任何白话 UI |

> **v0.5.0 起没有「自动让位」了。** 以前插件会去调用其它条目的 `select()`
> 问「你接不接」，然后自己翻转 —— 那套逻辑不可预测，而且 v0.4.3 的内存爆炸
> 恰好就发生在它选中的那条分支上。现在改成：你选一次，写进配置，一直生效。

`overlay` 模式下，如果打开了「在卡片内显示翻译摘要」，原生卡片的标题会是一行短摘要，例如：

> 说人话：查看内容，不改动任何文件（PowerShell 命令）（风险：安全）· 点卡片上的「说人话」看详情

**整段七段永远不会被塞进原生卡片**（对方的卡片是把 `displayReason` 当标题直接渲染的，
之前塞整段就是一坨不可读的纯文本）。

### 首次检测到冲突时的三选一

启动后如果**只读扫描**发现还有别的插件占用审批卡槽位，而你又从没选过模式，
右下角会弹**一次**选择，选完记住，永不再问：

- **A. 只用说人话（推荐）** → `takeover`
- **B. 让给对方，我用右下角浮窗** → `overlay`
- **C. 两个都不显示，回退到 DSH 原生** → `off`

提示本身是纯 React，走 DSH 的 `shell.overlay` 槽位渲染：不画自己的浮层 DOM、
不往 `document.body` 插节点、不注册全局监听器、不用 `MutationObserver`。

### 原生卡片里的「说人话」按钮（v0.4.5 已移除）

> ⚠️ **这个按钮在 v0.4.5 里被删掉了**，因为它就是 v0.4.2 / v0.4.3 卡死与内存爆满的根源：
> 它需要往 `dsh-reject-message` 的卡片里注入 DOM，而那段注入用了
> `MutationObserver` 观察整个 `document.body` 且在回调里无条件改 DOM，
> 形成微任务自激循环 —— 界面卡死、内存无限增长、渲染进程被系统杀掉。
>
> 现在的入口是**右下角固定浮窗**（`overlay` 模式），或直接用白话卡片（`takeover` 模式）。
> 不往任何别的插件的 DOM 里写东西，是这一版的安全底线。
>
> 想改模式？设置页「审批卡片模式」随时可切。

- **原生卡片默认不显示我们的摘要行**。想让卡片顶部多一行
  「说人话：…」，到 **设置 → 说人话 → 勾选「在卡片内显示翻译摘要」**
  （默认关闭；打开后也只有一行，不会塞整段七段）。

### 浮窗怎么用（v0.4.5：固定右下角，**没有拖动**）

| 操作 | 怎么做 |
|---|---|
| **位置** | **固定右下角**（由 CSS 决定）。拖动功能已在 v0.4.5 彻底删除 —— 它引入的位置状态与全局监听器是额外的风险面，而安全性优先。 |
| **展开 / 收起** | 浮窗里的「查看详情 ▾」按钮 |
| **折叠成一行** | 标题栏的 **▾** 按钮 → 只剩「说人话 · 点击展开」，点一下再展开 |
| **关闭浮窗** | 标题栏的 **✕** |

浮窗宽度**不超过屏幕宽度的 40%**（窄屏自动放宽），七段左对齐、段间留空行，
底部小字标注「本次翻译由：本地 Ollama / DeepSeek API」。

## 费用说明

- **通道 A（本地 Ollama）：永远 0 元。** 命令内容只在本机流转。
- **通道 B（DeepSeek API）：按 DeepSeek 官方计费，和 DSH 自己调用模型用的是同一个账户。**
  一次审批翻译大约 400-900 token（输入是命令 + 提示词，输出是一段 JSON），
  量级是**几厘到一两分钱**。

插件会在翻译结果下方显示：

```
本次翻译由：DeepSeek API
本次消耗 508 token，约 0.0017 元
当日累计：3 次 · 1524 token · 约 0.0051 元
```

**单价默认值**（设置页可改）：按 DeepSeek 官方定价页里 `deepseek-flash` 的
**峰时**价格换算成人民币（1 USD ≈ 7.2 元）：

| 项目 | 默认单价（元 / 百万 token） |
|---|---|
| 输入 · 缓存未命中 | 2.16 |
| 输入 · 缓存命中 | 0.0432 |
| 输出 | 8.64 |

> 选峰时价是刻意保守：宁可多显示一点，也不让用户在不知情的情况下花钱。
> 峰时 = UTC 周一至周五 01:00–04:00 与 06:00–10:00，其余时段（含周末、节假日）
> 是谷时，价格约为峰时的一半。**价格随时会变，请以
> <https://api-docs.deepseek.com/quick_start/pricing/> 为准，并按需在设置页改单价。**
> token 数是接口返回的真实用量，不是估算；只有「折算成钱」这一步是估算。

不想花钱？两种办法：
1. 引擎选「只用本地 Ollama」；
2. 保持自动降级，但打开「每次用 API 前先问我一次」——真正要花钱前会先弹一个确认。

## 边界情况与降级行为

设计红线：**宁可降级展示，也不能阻塞审批；宁可朴素，也不能让用户看不懂；
宁可多显示一行费用，也不能让用户在不知情的情况下消耗额度。**

| 情况 | 行为 |
|---|---|
| Ollama 未安装 / 未启动 | 不崩溃，降级到通道 B |
| `qwen2.5:7b` 未拉取 | 提示 `ollama pull qwen2.5:7b`，降级 |
| Ollama 超时（默认 10s） | 立即降级，绝不阻塞弹窗 |
| Ollama 返回非七段 / 空内容 | 尝试修复；修不了就贴原始返回并标注「翻译格式异常」；空内容直接降级 |
| DSH 未配置 API Key | 提示「通道 B 不可用，请配置 DeepSeek API Key 或启用本地 Ollama」 |
| Key 失效 / 余额不足 | 降级并提示检查账户 |
| API 超时（默认 15s） | 降级 |
| API 返回 429 | 指数退避（1s）重试一次，仍失败则降级 |
| 两个通道都不可用 | 显示「翻译不可用，请自行判断」+ 本地规则提示（不空白、不自动拒绝） |
| **命令超过 2000 字符（本地模型）** | 防 OOM：送进 Ollama 前截断，标注「命令过长，仅翻译前 2000 个字符（防 OOM：本地模型限制）」 |
| **本机可用内存 < 2GB** | 防 OOM：直接跳过 Ollama，改走 API，卡片上写明原因 |
| **同时来多条翻译** | 防 OOM：Ollama 串行执行（最多 1 条在跑），其余排队；队列满 5 条直接降级；同一条命令自动合并 |
| **本地模型连续失败 3 次** | 自动熔断 5 分钟，期间全部走 API；到点自动恢复；设置页显示熔断原因 |
| **本机显存 < 6GB 或内存 < 8GB** | 设备能力判「不可用」→ 强制走 API；想强行开本地必须点「我明白风险，仍要启用」，之后每次本地翻译都在卡片上提示「本地配置不足」 |
| **强行开本地后又连续 2 次失败** | 自动切回 API，本地通道临时禁用 30 分钟；设置页有「恢复本地通道」按钮 |
| **读不到会话上下文** | 「背景」段固定写「未读取到会话上下文，仅翻译命令本身。」——模型编的内容也会被覆盖 |
| 命令超过 4000 字符 | 截断后翻译，标注「命令过长，仅翻译前 4000 字符」 |
| 管道链 `A \| B \| C` | 逐段解释 + 整体总结 |
| 多行脚本 | 按行拆解 + 整体总结 |
| 含 base64 / `-enc` / `iex` 等 | 标「危险」+「建议拒绝」+「无法可靠解释」 |
| 含 `rm -rf` / `del /f /s /q` / `format` / `diskpart` / `reg delete` | 直接「危险 / 建议拒绝 / 可能永久删除文件，无法恢复」（不走模型，也不花钱） |
| **URL 只指向本机/内网**（`127.0.0.1`、`localhost`、`::1`、`10.x`、`172.16-31.x`、`192.168.x`、`*.local`） | **不算联网下载**；后果写「检测到本地接口调用（127.0.0.1），属于本机服务探测，不涉及外网下载。」——本地规则**权威覆盖**模型判断 |
| **删除目标全是临时文件**（路径含 `Temp` / `AppData\Local\Temp` / `Cache`，扩展名 `.log/.tmp/.cache/.dmp`） | 降为**安全 / 可以允许**，后果写「删除的是临时日志/缓存文件，不影响项目数据和系统安全。」 |
| 删除目标含 `C:\Windows\` / `C:\Program Files\` / `C:\ProgramData\` / `/etc` / `/usr` | **保持危险 / 建议拒绝**，后果写「可能永久删除系统文件，无法恢复。」 |
| 含 curl / wget / Invoke-WebRequest（外网） | 标注下载来源与落地路径 |
| 含 chmod / icacls / takeown | 标「修改文件权限，注意」 |
| 含注册表修改 | 标「修改注册表，注意」 |
| 含 sudo / runas / 提权 | 标「要求管理员权限」 |
| 空命令 / 纯空格 | 显示「空命令，无可翻译内容」 |
| **极其罕见的**：宿主从会话里取不到命令原文 | 仍然渲染卡片，标注「未能取到命令原文」；客户端会用自己读到的命令补齐翻译 |

### 哪些情况会「不走模型」

只有**一条**分支会跳过模型，而且**照样渲染完整的七段白话卡片**：

| 分支 | 条件 | 为什么 |
|---|---|---|
| `local-danger` | 本地规则判定「危险」（破坏性关键词 / 编码混淆 / 自定义黑名单） | 这种结论必须由代码给出，不能让模型推翻；顺带省时省钱 |
| `empty` | 命令为空 | 没有可翻译内容 |
| `unavailable` | 两个通道都不可用 | 已降级 |

其余所有审批（极短命令、纯文件读取、临时文件清理、本地接口调用、普通写入……）
都走正常翻译链路。所以**不存在「某类命令不显示白话卡片」的情况**。

界面行为：翻译结果在原始命令上方（不藏折叠里）；耗时超过约 2 秒时先显示
「正在翻译…」占位再替换；用户在翻译完成前点了允许/拒绝，翻译请求立即取消；
结果下方始终标注「本次翻译由：本地 Ollama / DeepSeek API」。

## 隐私与安全

- **通道 A**：命令内容只发给本机 `127.0.0.1:11434`，不联网、不上传任何外部服务器。
- **通道 B**：命令内容**会发送到 DeepSeek 官方 API**。设置页对此有明确警告，
  并且第一次真的要花钱时会弹一次确认。
- **缓存 / 设置 / 日志** 全部位于 `$DSH_HOME/plain-approval/`，不散落在工作区。
- **日志只记命令哈希（sha256 前 16 位），不记命令原文。**
- **审计日志**（`audit.jsonl`）只记：时间 / 命令哈希 / 翻译结果（七段）/ 授权规则 ID /
  工作区；**不含命令原文**。
- **长期同意授权表**（`grants.json`）存完整 SHA-256 与前 160 字预览 ——
  预览是为了让设置页能显示「你授权了哪条命令」并支持逐条撤销；
  完整命令原文不会被保存。
- HTTP 接口只监听 webserver 配置的回环地址，写操作要求插件自定义请求头（挡跨站请求），
  接口也永远不会回传 API Key 原文。

## 常见问题排查

**Q：卡片没变成白话卡片，而是右下角多了一个小条。**
说明当前是 `overlay` 模式（`ui.slotMode: overlay`）：说人话**主动不接管**审批卡，
把卡片让给别的插件（本机上是 `dsh-reject-message`），翻译改在右下角浮层里给。
点浮层上的「查看详情 ▾」就能看到完整七段。
想让白话卡片接管：**设置 → 说人话 → 审批卡片模式 → 接管**。
设置页里还会显示「当前状态」和检测到的占用者，一眼就知道跟谁冲突。

> v0.5.0 起这个模式**只由设置决定，插件不会自己切换**。
> 如果你从没选过而看到了这个界面，说明启动时检测到冲突并弹过一次三选一
> （或者你以前用的是旧的「自动让位」，已自动迁移成接管模式）。

**Q：初始向导点「下一步」报「未知接口：POST /api/plain-approval/onboard」。**
**宿主（Node 侧）还是旧版本** —— 浏览器已经加载了新版 `client.js`，但 DSH 进程里
跑的仍是老代码，所以新接口不存在。这是**必须重启一次**的操作：

1. 完全退出 DeepSeek Harness（**托盘图标 → 退出**，不是关窗口）；
2. 重新启动，回到 `http://127.0.0.1:19387`；
3. 刷新页面。

判断方法：看 `$DSH_HOME/plain-approval/plain-approval.jsonl` 里最后一条 `host.loaded`
的 `version` 是不是当前版本号 —— 不是就说明没重启成功。

> v0.4.1 起，即使你没重启，向导也**不会再卡住**：它会自己关掉，
> 并提示「宿主还是旧版本，请重启」。

**Q：向导说我「本机配置偏低 / 可能导致卡顿甚至卡死」，但我有 12GB 独显。**
v0.4.0 的判定 bug，v0.4.1 已修：

- 内存阈值原来要求 `>= 16GB`，而 Windows 会保留一部分内存，装 16GB 的机器只报
  15.47GB → 永远够不到 → 误判「偏低」。现在带 1GB 容差。
- 读不到硬件信息时不再判「不可用」，改为「未检测到具体硬件信息，建议使用 API」，
  不拦你、也不强制勾风险确认。
- **只要 Ollama 在跑且模型在，就完全不弹风险警告。**

如果还是显示偏低，可以先在**设置 → 说人话 → 本机能力检测**看它读到了什么；
读不到显卡就手动填一个显存值（`device.manualVramGB`），填了就按你给的算。

**Q：设置页/卡片显示 HTTP 404。**
v0.1 有这个 bug（路由前缀多了一个尾斜杠），v0.2 已修复；
v0.4.1 又补了一层「宿主版本旧也能优雅退出向导」的容错。
如果还看到 404，先确认装的是 **0.4.1**，并**重启 DSH**。

**Q：卡片上写着「翻译不可用，请自行判断」。**
说明两个通道都没通。打开 **设置 → 说人话** 看两个状态灯的红色提示，
再点「一键测试两个通道」，把结果连同「导出诊断日志」一起反馈。

**Q：通道 A 状态灯黄了。**
Ollama 起来了但没拉模型。按提示执行 `ollama pull qwen2.5:7b`。

**Q：通道 A 经常超时。**
本地模型冷启动慢是正常的。可以把 `ollama.timeoutMs` 调大（例如 60000），
或者干脆用默认的自动降级——超时会自动走 DeepSeek。

**Q：我不想消耗 DeepSeek 额度。**
设置里：引擎选「只用本地 Ollama」；或者打开「每次用 API 前先问我一次」。

**Q：翻译出来的「干什么」太长/不好懂。**
提示词已限制「干什么」不超过 40 个汉字。如果本地模型不听话，可以换一个更大的模型
（改 `ollama.model`）。模型不可用时，本地规则给出的兜底文案是可用的。

**Q：`format`、`diskpart` 这类命令被标红，是不是误报？**
不是误报。它们**本来就是**能造成不可恢复损失的命令。插件对破坏性关键词一律
「危险 / 建议拒绝」，并且不让模型来推翻这个判断。

**Q：日志在哪？**
`$DSH_HOME/plain-approval/plain-approval.jsonl`。设置页的「导出诊断日志」
会把它整理成 JSON 下载。日志里只有命令哈希，没有命令原文。

## 已知限制

- **审批卡片槽位是「一个位置只有一个主人」**（DSH 的 chain 槽位机制），
  所以本插件和别的审批卡插件**不可能同时渲染卡片**。
  - v0.5.0 起模式是**固定**的，由设置页「审批卡片模式」决定（`takeover` /
    `overlay` / `off`），插件**不做任何自动判定**，也不会自己改变。
  - 选 `overlay` 时，说人话显示在右下角的 `「说人话 · 查看详情 ▾」` 浮层里，
    点开才触发模型翻译。
  - `overlay` 模式下**不会**把内容显示在对方的卡片内部 —— DSH 的槽位模型不允许
    一个插件往另一个插件的卡片里塞内容，所以只能用独立的浮层。
- **冲突检测是「只读 + 一次性」的**，而且刻意做得很笨：只扫条目元数据
  （locale / registrant / 组件名），不调用任何人的 `select()`。
  代价是**可能漏报或误报**：
  - 一个装得很深、`registrant` 与组件名都拿不到的插件，可能显示成
    `第三方插件(priority=-7)` 这种占位；
  - 一个注册了槽位但实际从不接手的插件，也会出现在冲突列表里。
  这类误报**只影响一句提示文字**，不会改变任何行为 —— 真正的行为只由
  `ui.slotMode` 决定。宁可提示得糙一点，也不要为了「判得准」再去调别人的选择器。
- **冲突提示只问一次**（`ui.conflictResolved`）。选了之后即使你后来装了新的
  抢卡插件，也不会再问 —— 需要时请到设置页手动改模式。
- 本地 Ollama 冷启动较慢（本机实测 20–35 秒），首条命令可能直接降级到通道 B。
- 费用单价是内置默认值，DeepSeek 调价后需要手动同步（设置页可改）。
- 「使用 API 前确认」是一个卡片内嵌的确认条，不是全局模态框。
- 长期同意授权表存了命令的前 160 字预览（用于设置页展示与撤销）；
  如果你连这个都不能接受，删掉 `grants.json` 里的 `preview` 字段即可
  （匹配用的是哈希，不受影响）。
- 浮层位置固定在右下角（`bottom: 120px`）；如果与其他插件的浮层重叠，
  改 `client.js` 里 `.pap_chipRoot` 的 `bottom` / `right` 即可。
- **默认不推荐本地模型**：`engine` 默认 `auto`（API 优先），链路里没有 Ollama。
  想用本地免费翻译，请在设置页选「本地优先」，并且需要自己装 Ollama。
- **设备检测只看 GPU/内存**：本机没检测到独立 GPU 时会判「不可用」
  （CPU 跑 7B 模型虽然能跑但极慢且吃内存）。判断是保守的，可以点
  「我明白风险，仍要启用本地通道」覆盖。
- **「背景」段依赖会话事件流**：如果某个审批不是由对话触发的（例如后台任务），
  读不到上下文就会固定写「未读取到会话上下文，仅翻译命令本身。」——这是刻意的，
  宁可少说也不许编。
- **防 OOM 的并发上限对两个通道统一生效**：本插件的所有翻译串行排队，
  不会出现「同一秒解析十条命令」把机器压垮的情况。
- **「长期同意」的工作区范围 = DSH 宿主进程的 `process.cwd()`**
  （本机实测是 `C:\Users\alpha\.dsh\profiles\desktop`），不是对话里显示的
  Agent 工作目录。所以它是「每个 DSH profile 一份」：换 profile 不生效，
  同一 profile 下跨对话通用。需要更细粒度时，只能用「一键清空 + 重新授权」。
- **设备检测的 GPU 显存主要靠 `nvidia-smi`**：AMD / Intel 核显只能拿到型号与
  近似显存（`wmic` 的 `AdapterRAM` 在 >4GB 时溢出），此时档位判定偏保守；
  读不到就判「未知」而不是「不可用」，你可以在设置页**手动填显存**覆盖它。
- **原生卡片里的「说人话」按钮已随 v0.4.6-safe 一并移除**（详见下方硬性限制）。
- **浮窗在窄屏上会放宽到 92vw**：否则 40vw 在手机上只有 100 多像素，完全读不了。
- **上下文感知仍是「命令级」**：DSH 目前没有把会话消息随审批事件一起给出的接口，
  所以「背景」段常常会写「未读取到会话上下文，仅翻译命令本身。」。
  代码里已经把来源抽象成 `extractContext()`，DSH 一开放新接口就能直接接上，
  不需要改上层逻辑。

### v0.4.6-safe 的硬性限制（本次事故后永久生效）

以下几条不是「还没做的功能」，而是**为了不再撑爆 DSH 而主动放弃的**。请不要试图改回来：

- **浮窗不可拖动，且不会再有拖动功能**。位置由 CSS 固定在右下角
  （`.pap_chipRoot` 的 `right: 20px; bottom: 120px`），不受鼠标影响。
  理由：拖动相关的 pointer 事件、位置状态与 `localStorage` 记忆已整段移除；
  设置页里的「复位位置」入口也一并删除（浮窗根本不会跑到别处去）。
  想改位置，只改 `client.js` 里 `.pap_chipRoot` 的 `bottom` / `right`。
- **插件不往别的插件的 DOM 里插任何东西**。
  v0.4.2 / v0.4.3 的内存爆炸就来自这里：`MutationObserver` 监听
  `document.body` 全子树，回调里再无条件改 DOM，形成微任务自激循环，
  几秒内把渲染进程撑到 GB 级并被系统强杀（`Desktop renderer exited: killed`）。
  现在客户端**完全不做直接 DOM 操作**，源码里 `new MutationObserver`、
  `.observe(`、`window.addEventListener`、`document.addEventListener`
  全部为 0，并写成测试红线（X1–X4）。
  代价：原生审批卡片里**不再有**「说人话」按钮；`overlay` 模式下白话只出现在右下角浮层。
- **诊断上报有频率上限**：所有 `note` 类上报 5 秒内最多 12 次，超出的**直接丢弃**。
  这是防止任何渲染循环再次被请求放大成 OOM 的最后一道闸门。
  如果你看到 `plain-approval.jsonl` 里某些事件偶尔缺失，那是限流在工作，属于正常。
- **翻译结果缓存最多保留 8 条**：长会话里更早的结果会被淘汰，重新点开会再查一次。
  这是为了不让浮窗的状态无限增长。
- **本版已完成验证的范围**：离线自测 **202 项全过**；
  真机 DSH 上「接管路径」审批瞬间最大单进程 301 MB、随后自动回落、无崩溃（v0.4.6-safe 实测）。
  **v0.5.0-stable 尚未在真机上跑过** —— 它是 v0.4.6-safe 的删减版（删代码、不改行为），
  但仍需实测确认。**尚未覆盖**：`overlay` 模式浮窗、真实模型翻译（非缓存命中）、
  危险命令标红、设置页各功能项、首次冲突三选一。
  升级与验收步骤见 [升级指南](./升级指南-v0.5.0-stable.md)。

## 路线图

### 当前状态：**等待真机数据**（v0.5.3）

本插件的风险等级来自**本地正则 + 语言模型**判断，**这个判断到底有多准，从来没被验证过**。
而 v0.4.2/v0.4.3 那次内存爆炸恰恰说明：在这个项目里，「规则说安全」这件事翻过车。

所以从 v0.5.3 起，我们**先不做任何自动放行**，改为先把**证据**攒起来：

> **v0.6.0 的前置条件：用 2–4 周真实审批历史，验证「本地规则判安全」的准确率。**
>
> 具体要看的是：标绿的那些操作里，有多少其实不该绿。
> 如果误判率不可接受，自动放行这个功能就不该做 —— 这不是拖进度，是避免给用户一个
> 「看起来更省事、实际上更危险」的功能。

打开 **设置 → 说人话 → 审批历史 → 查看历史**，就能看到攒下来的数据。
它也按决定类型分桶统计，可以直接看出「自动放行 / 手动允许 / 拒绝」各占多少。

### v0.6.0（计划中）

| 功能 | 状态 | 前置条件 |
|---|---|---|
| 低风险操作自动通过 | ⏸ 等待数据 | 准确率达标 |
| 同类操作授权（模式匹配） | ⏸ 等待数据 | 准确率达标 |
| 审批偏好学习 | ⏸ 最后考虑 | 见下方说明 |

设计时已经定死的安全底线（**即使做也不会突破**）：

1. **默认关闭**，用户主动开启才生效；
2. **删除、格式化、权限变更、注册表、系统目录**永远不自动放行；
3. **工作区外的操作**即使只读也不自动放行；
4. 所有自动放行写审计日志，并在历史里可查；
5. 用户随时可关掉并清空所有授权与学习数据；
6. 数据完全本地，不上传。

### 关于「审批偏好学习」，我们保留意见

原计划是「某类操作连续 10 次被允许且风险=安全，就提示要不要开启自动通过」。
**这个设计我们没有实现，也不打算按原样实现。**

它的机制本质上是**用过去的行为降低未来的审查强度**：
你点得越多，被问得越少，直到某天系统在你没细看的情况下放行了一个你其实不想放的东西。
这在安全设计上是有名的问题（规范性麻木）。

如果你想要类似的东西，我们建议的替代形态是：

- **只统计、只展示**，不自动改变任何行为；
- 把「你最近 30 天拒绝了什么」明确列出来 —— **拒绝的记录比允许的更有价值**；
- 建议由你主动发起，而不是由插件在你放松警惕时提议。
